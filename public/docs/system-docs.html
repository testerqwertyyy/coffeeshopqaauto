1. Краткое описание проекта

Artisan Roast — полнофункциональное веб-приложение электронной коммерции, специализирующееся на продаже спешелти-кофе. Система предоставляет конечным пользователям возможность просматривать каталог кофе, фильтровать по степени обжарки, управлять корзиной и оформлять заказы. Административная часть включает управление товарами через seed-данные и отслеживание заказов.

💡 Ключевая особенность Система построена по классической трёхзвенной архитектуре: клиент (SPA) → API-сервер → реляционная БД. Все взаимодействия между фронтендом и бэкендом происходят через RESTful API с JWT-аутентификацией.

2. Цели и задачи системы

Бизнес-цели

  • Предоставить покупателям удобный каталог спешелти-кофе с детальной информацией о каждом лоте
  • Обеспечить полный цикл покупки: просмотр → корзина → оформление → история заказов
  • Персонализировать опыт через регистрацию и привязку корзины/заказов к аккаунту

10–14. API Reference

Все endpoints начинаются с префикса /api. Аутентифицированные endpoints требуют заголовок Authorization: Bearer <jwt_token>.

10. Auth — Аутентификация

POST /api/auth/register public

Регистрация нового пользователя. При успехе возвращает JWT-токен.

Request Body

{
  "email": "john@example.com",
  "username": "john",
  "password": "secret123",
  "full_name": "John Doe"     // optional
}

Response 200

{
  "access_token": "eyJhbGciOi...",
  "token_type": "bearer",
  "user": { "id": 1, "email": "...", "username": "john", ... }
}

Errors

  • 400 — Email already registered / Username already taken
POST /api/auth/login public

Аутентификация пользователя. Возвращает JWT-токен.

Request Body

{ "username": "john", "password": "secret123" }

Errors

  • 401 — Invalid credentials
GET /api/auth/me 🔒 required

Получение профиля текущего пользователя по JWT-токену.

11. Products — Каталог

GET /api/products public

Получение списка товаров с опциональными фильтрами.

12. Cart — Корзина

GET /api/cart 🔒 required

Получение содержимого корзины текущего пользователя с итогами.

Response 200

{
  "items": [
    { "id": 1, "product_id": 1, "quantity": 2,
      "product": { "id": 1, "name": "Ethiopia Yirgacheffe", "price": 24.99, ... } }
  ],
  "total_items": 2,
  "total_price": 49.98
}
POST /api/cart 🔒 required

Добавление товара в корзину. Если товар уже есть — увеличивает quantity.

{ "product_id": 1, "quantity": 2 }
PUT /api/cart/{item_id} 🔒 required

Обновление количества. Если quantity ≤ 0 — удаляет позицию.

{ "quantity": 5 }
DELETE /api/cart/{item_id} 🔒 required

Удаление одной позиции из корзины.

DELETE /api/cart 🔒 required

Полная очистка корзины пользователя.

13. Orders — Заказы

POST /api/orders 🔒 required

Создание заказа из текущего содержимого корзины. Корзина очищается, stock уменьшается.

Request Body

{
  "customer_name": "John Doe",
  "customer_email": "john@example.com",
  "address": "123 Coffee Street",
  "city": "Portland",
  "zip_code": "97201"
}

Алгоритм (транзакция)

  1. Проверка: корзина не пуста → иначе 400
  2. Создание записи Order с расчётом total
  3. Для каждой позиции корзины → создание OrderItem (snapshot цены)
  4. Уменьшение product.stock на quantity
  5. Удаление всех позиций корзины пользователя
  6. Commit транзакции
GET /api/orders 🔒 required

Получение всех заказов текущего пользователя (отсортированы по дате, новые сверху).

GET /api/orders/{order_id} 🔒 required

Получение конкретного заказа. Проверяется принадлежность текущему пользователю.

20. JWT-аутентификация

sequenceDiagram participant FE as Frontend participant MW as FastAPI Middleware participant H as get_current_user() participant DB as SQLite FE->>MW: Request + Header: Authorization: Bearer MW->>H: Depends(security) H->>H: jwt.decode(token, SECRET, [HS256]) alt Токен истёк / невалиден H-->>FE: 401 {detail: "Invalid token"} else Токен валиден H->>H: payload.get("sub") → user_id H->>DB: SELECT * FROM users WHERE id=user_id alt Пользователь не найден H-->>FE: 401 {detail: "User not found"} else OK H-->>MW: User object MW->>MW: Продолжает обработку запроса end end

Структура JWT-токена

// Payload
{
  "sub": 1,                    // user.id
  "exp": 1705334400            // Unix timestamp (now + 24h)
}

// Header
{
  "alg": "HS256",
  "typ": "JWT"
}

// Signature
HMACSHA256(base64(header) + "." + base64(payload), SECRET_KEY)
🔒 Production Checklist Перед выкладкой в продакшен необходимо:
  • Заменить SECRET_KEY на случайную строку (min 32 символа)
  • Заменить SQLite на PostgreSQL/MySQL
  • Настроить CORS allow_origins на конкретные домены
  • Добавить rate limiting на endpoints авторизации
  • Включить HTTPS на сервере
